jeu-iq documentation¶

Présentation¶

Ce projet est une version digitale des puzzles IQ. Ces jeux sont des jeux de logique destinés à un seul joueur.

Le principe est de placer différentes pièces sur un plateau afin de remplir toutes les cases disponibles. Certaines contraintes peuvent exister, comme des cases dans lesquelles il est impossible de placer des pièces.

L’objectif du projet est de créer une application web interactive dans laquelle le joueur peut manipuler les pièces avec la souris, les placer sur une grille et résoudre un puzzle.

Fonctionnalités¶

Actuellement, l’application permet :

  • d’afficher un plateau dont la taille est définie par l’utilisateur ;

  • de générer automatiquement des pièces en fonction de cette taille ;

  • de déplacer les pièces avec la souris ;

  • de faire pivoter les pièces ;

  • de placer les pièces sur le plateau ou de les remettre dans leur zone.

L’utilisateur peut également :

  • modifier la largeur et la hauteur du plateau ;

  • choisir un préréglage de difficulté ;

  • personnaliser le pourcentage d’obstacles ;

  • personnaliser la taille minimale et maximale des pièces ;

  • générer un nouveau puzzle ;

  • réinitialiser le plateau en remettant toutes les pièces dans leur zone initiale.

Enfin, un message de victoire s’affiche lorsque le puzzle est résolu, avec un retour à l’accueil.

Technologies utilisées¶

Ce projet utilise diverses technologies pour son bon fonctionnement :

  • HTML : il est utilisé pour la structure de l’interface du jeu, comme les boutons, les textes et les zones d’affichage du plateau et des pièces.

  • CSS : il sert à gérer l’apparence du jeu, comme les couleurs, la disposition des éléments, le style des boutons et l’aspect visuel du plateau et des pièces.

  • JavaScript : il sert à programmer le fonctionnement du jeu, c’est-à-dire la génération du puzzle, le déplacement des pièces, la vérification des placements et la détection de la victoire.

  • SVG : il est utilisé pour dessiner le plateau et les pièces du puzzle, car cela permet d’afficher des formes précises, redimensionnables et faciles à manipuler.

  • Sphinx / reStructuredText : ils sont utilisés pour rédiger et générer la documentation du projet.

Structure du projet¶

Le projet est organisé en plusieurs fichiers qui séparent l’interface, le style, la logique du jeu et la documentation.

Fichiers principaux¶

  • index.html : page principale de l’application. Elle contient les éléments de l’interface utilisateur, comme les paramètres de génération, les règles du jeu, le plateau, la zone des pièces et les boutons d’action.

  • style.css : feuille de style de l’application. Elle gère l’apparence générale, la disposition des éléments, l’affichage du plateau, des pièces, des boutons, des messages et des états visuels du jeu.

  • js/ : dossier contenant la logique JavaScript du projet, découpée en plusieurs modules spécialisés.

Organisation du dossier js¶

  • js/script.js : point d’entrée principal. Il importe les différents modules, relie les fonctions au système d’état global et initialise l’interface ainsi que les interactions du jeu.

  • js/data.js : centralise les constantes, les références vers les éléments du DOM, les paramètres de difficulté et l’état global de la partie.

  • js/ui.js : gère les interactions avec les contrôles de l’interface (boutons, choix de difficulté, champs personnalisés).

  • js/game.js : gère la création d’une nouvelle partie, la mise à jour des paramètres choisis par l’utilisateur et le passage entre l’écran d’accueil et l’écran de jeu.

  • js/board.js : initialise et dessine le plateau de jeu.

  • js/pieces.js : génère les pièces du puzzle en fonction de la taille de la grille et des contraintes choisies.

  • js/draw-pieces.js : affiche graphiquement les pièces dans leur zone de réserve ou sur le plateau.

  • js/obstacle.js : génère les obstacles sur la grille.

  • js/drag.js, js/drag-start.js, js/drag-helpers.js : gèrent le système de déplacement des pièces avec la souris.

  • js/snap-place.js et js/placement.js : vérifient et appliquent le placement des pièces sur le plateau.

  • js/win.js : détecte la victoire, affiche le message de fin et gère le retour à l’écran d’accueil ou la réinitialisation.

  • js/timer.js : gère le chronomètre de la partie.

  • js/svg-helpers.js : fournit des fonctions utilitaires pour la création et la manipulation des éléments SVG.

  • js/utils.js : contient des fonctions utilitaires réutilisées dans plusieurs modules.

Documentation et outils¶

  • index.rst : fichier principal de la documentation Sphinx.

  • conf.py : configuration de Sphinx.

  • README.md : présentation rapide du projet et consignes de lancement.

  • Makefile et make.bat : commandes permettant de générer la documentation.

  • _build/ : fichiers générés par Sphinx.

  • _static/ et _templates/ : ressources complémentaires utilisées par la documentation.

Fonctionnement interne¶

Le fonctionnement de l’application repose sur plusieurs modules JavaScript qui coopèrent pour générer une partie, afficher le puzzle et gérer les interactions du joueur.

1. Initialisation¶

Lorsque la page s’ouvre, le fichier js/script.js lance l’application. Il importe les modules principaux, associe plusieurs fonctions au système central d’état, puis appelle notamment initDragHandlers(), resetTimer() et initUI() afin de rendre l’interface immédiatement utilisable.

2. Gestion de l’état du jeu¶

Le fichier js/data.js centralise les informations partagées par tout le programme. Il contient notamment :

  • la taille du plateau ;

  • la grille logique de la partie ;

  • la liste des obstacles ;

  • les pièces générées ;

  • la pièce en cours de déplacement ;

  • les paramètres de difficulté ;

  • l’état de victoire ;

  • les références vers les éléments HTML et SVG.

Cette centralisation permet aux autres modules de lire et de modifier les mêmes données pendant toute la partie.

3. Paramétrage et lancement d’une partie¶

Les interactions avec les boutons et les champs de saisie sont préparées dans js/ui.js grâce à initUI().

Lorsque le joueur change la difficulté, updateSettingsFromDifficulty() dans js/game.js applique les valeurs correspondant au niveau choisi. Si le joueur utilise le mode personnalisé, updateSettingsFromCustomInputs() vérifie les valeurs saisies et les adapte aux limites prévues par le jeu.

Quand le joueur clique sur Commencer, initUI() déclenche ensuite generateGame() dans js/game.js.

Cette fonction :

  • enregistre la largeur et la hauteur du plateau ;

  • réinitialise certains états liés à la victoire ;

  • génère les obstacles avec generateObstacles() dans js/obstacle.js ;

  • crée la grille logique avec initBoard() ;

  • génère les pièces avec generateSimplePieces() dans js/pieces.js ;

  • démarre le chronomètre avec startTimer() ;

  • redessine le plateau et les pièces avec drawBoard() et drawPieces().

4. Génération du plateau et des pièces¶

Le plateau est représenté sous forme de grille logique, puis affiché en SVG. Le module js/board.js prépare cette grille et dessine visuellement les cases ainsi que les obstacles.

Les obstacles sont produits par generateObstacles() dans js/obstacle.js, qui marque certaines cases comme interdites.

Les pièces sont créées dans js/pieces.js par generateSimplePieces(). Cette fonction parcourt les cases libres du plateau et les regroupe en formes connexes de tailles variables afin de produire l’ensemble des pièces du puzzle.

5. Affichage graphique¶

L’affichage repose sur le format SVG, qui facilite le placement précis des formes. Le module js/draw-pieces.js affiche les pièces soit dans la zone de réserve, soit sur le plateau selon leur état.

Des fonctions utilitaires regroupées dans js/svg-helpers.js servent à créer et à manipuler les éléments graphiques nécessaires à l’affichage.

6. Déplacement et rotation des pièces¶

Le déplacement des pièces est géré par plusieurs modules complémentaires :

  • js/drag.js met en place les événements liés au déplacement ;

  • js/drag-start.js gère le début de la prise d’une pièce ;

  • js/drag-helpers.js fournit des fonctions utilitaires liées à ce comportement.

Selon l’endroit où se trouve la pièce, le programme utilise startDragFromTray() si elle vient de la réserve, ou startDragFromBoard() si elle était déjà posée.

Pendant le déplacement, le joueur peut faire pivoter la pièce. Cette action est prise en charge par rotateDraggedPiece(), qui modifie l’orientation de la forme avant la tentative de pose.

7. Vérification et placement¶

Quand le joueur relâche une pièce, snapAndPlace() dans js/snap-place.js convertit la position de la souris en coordonnées de grille.

La validité du placement est ensuite testée par canPlaceAt() dans js/placement.js. Cette fonction vérifie que :

  • la pièce reste dans les limites du plateau ;

  • la pièce ne recouvre pas un obstacle ;

  • la pièce ne recouvre pas une case déjà occupée.

Si la pose est possible, placePieceOnBoard() inscrit la pièce dans la grille logique et met à jour sa position. Si elle ne l’est pas, la pièce est renvoyée vers sa position précédente ou vers la zone de réserve.

8. Détection de la victoire et fin de partie¶

Après chaque placement, checkWin() dans js/win.js parcourt la grille logique pour vérifier si toutes les cases libres ont été remplies.

Lorsque la partie est gagnée :

  • stopTimer() arrête le chronomètre ;

  • showWinMessage() affiche le message de victoire ;

  • le temps final est présenté au joueur ;

  • returnToStartup() permet ensuite de revenir à l’écran d’accueil.

9. Réinitialisation¶

Le joueur peut également relancer l’organisation des pièces sans créer un nouveau puzzle. Dans ce cas, resetPlacedPieces() dans js/win.js :

  • remet l’état de victoire à zéro ;

  • reconstruit la grille à partir des obstacles existants ;

  • retire les pièces placées ;

  • replace toutes les pièces dans leur zone initiale ;

  • redessine le plateau et les pièces.

Limites et améliorations possibles¶

Même si le projet est jouable et fonctionnel, certaines limites restent présentes dans sa version actuelle.

Limites du projet¶

  • La difficulté repose principalement sur la taille du plateau, le nombre d’obstacles et la taille des pièces. Elle n’est donc pas encore fondée sur des puzzles conçus individuellement avec une solution précise.

  • La vérification de victoire consiste surtout à contrôler que toutes les cases libres du plateau sont remplies. Le programme ne compare pas encore la disposition finale des pièces à une solution prédéfinie.

  • Le projet reste centré sur une utilisation à la souris. Il ne comporte pas encore de commandes clavier ou d’améliorations spécifiques liées à l’accessibilité.

Améliorations possibles¶

Il est possible d’ajouter des modifications afin de faire évoluer le projet :

  • créer une liste de niveaux ou de défis prédéfinis avec une difficulté progressive ;

  • associer chaque défi à une solution connue afin de renforcer la vérification de la résolution ;

  • améliorer les effets visuels lors du déplacement et du placement des pièces, par exemple avec des surbrillances ou des animations ;

  • enrichir l’interface avec davantage d’informations pour le joueur, comme un meilleur guidage, des messages d’erreur plus explicites ou des aides contextuelles ;

  • proposer d’autres options de jeu, comme un mode chronométré, un système de score ou des statistiques de partie.

Installation¶

Pour installer le projet :

  • assurez-vous d’avoir installé Git et Visual Studio Code avant de commencer ;

  • copiez le lien HTTPS du dépôt GitHub ;

  • ouvrez Visual Studio Code et un terminal dans VS Code ;

  • clonez le projet avec la commande git clone https://github.com/isabellatc06/jeu-iq.git ;

  • accédez au dossier du projet avec cd jeu-iq ;

  • ouvrez le projet avec code ..

Pour lancer le jeu :

  • cherchez dans les fichiers le fichier index.html ;

  • faites un clic droit sur le fichier index.html ;

  • choisissez l’option Open with Live Server ;

  • si l’extension n’est pas installée, ajoutez Live Server de Ritwick Dey dans l’onglet des extensions.

Utilisation¶

L’utilisation du jeu suit plusieurs étapes, depuis la préparation de la partie jusqu’à sa résolution.

1. Choix des paramètres¶

Avant de lancer une partie, le joueur choisit une difficulté prédéfinie ou active le mode personnalisé. Dans ce mode, il peut modifier :

  • la largeur du plateau ;

  • la hauteur du plateau ;

  • le pourcentage d’obstacles ;

  • la taille minimale des pièces ;

  • la taille maximale des pièces.

Ces réglages permettent d’adapter la partie au niveau souhaité.

2. Lancement de la partie¶

Quand le joueur clique sur Commencer, le jeu génère un nouveau puzzle. Le plateau est créé selon les paramètres choisis, les obstacles sont placés et les pièces correspondantes apparaissent dans leur zone de réserve.

Le chronomètre démarre également au lancement de la partie.

3. Déplacement des pièces¶

Une fois la partie commencée, le joueur peut cliquer sur une pièce pour la prendre puis la déplacer avec la souris jusqu’à l’endroit souhaité.

Les pièces peuvent venir soit de la zone de réserve, soit du plateau si elles ont déjà été placées auparavant.

4. Rotation des pièces¶

Pendant qu’une pièce est en cours de déplacement, le joueur peut faire un clic droit pour la faire pivoter. Cela permet d’essayer différentes orientations afin de l’adapter à l’espace disponible sur le plateau.

5. Placement sur le plateau¶

Lorsque le joueur relâche une pièce, le jeu vérifie si elle peut être posée à cet endroit.

Le placement est accepté seulement si :

  • la pièce reste dans les limites du plateau ;

  • la pièce ne recouvre pas un obstacle ;

  • la pièce ne recouvre pas une case déjà occupée.

Si le placement est valide, la pièce reste sur le plateau. Sinon, elle revient à sa position précédente ou dans sa zone de réserve.

6. Réinitialisation¶

Le bouton Réinitialiser les pièces permet de recommencer le placement sans générer un nouveau puzzle.

Dans ce cas, le plateau conserve sa forme et ses obstacles, mais toutes les pièces sont retirées puis remises dans leur zone initiale.

7. Fin de partie¶

Après chaque placement, le jeu vérifie si toutes les cases libres du plateau sont occupées.

Lorsque le puzzle est résolu :

  • le chronomètre s’arrête ;

  • un message de victoire s’affiche ;

  • le temps final est indiqué au joueur ;

  • un retour à l’accueil est proposé.

Utilisation de l’intelligence artificielle¶

Nous avons utilisé une intelligence artificielle, notamment Codex (dans une version récente basée sur les modèles GPT-5 Codex), comme aide au développement de certaines parties du projet.

Elle nous a surtout aidés à :

  • corriger des erreurs dans le code JavaScript ;

  • proposer ou compléter certaines fonctions ;

  • améliorer la structure de certaines parties du projet ;

  • reformuler ou améliorer certains éléments de documentation.

Les idées générales du projet, les choix de conception, les tests, les ajustements et la compréhension du fonctionnement ont été réalisés par nous-mêmes.

Nous ne disposons plus de l’historique exact de tous les prompts utilisés ; cette description est donc faite de manière honnête mais approximative.
